# M4 操作手册 —— 前台服务 + 开机自启 + 看门狗自恢复

> 真机：荣耀 200 / MagicOS 10.0.0.175 / Android 16 (API 36)
> 前置：M1（预览+夜视）、M2（识别）、M3（报警）已完成

---

## 〇、先说最重要的一句话

**M4 和前面三个里程碑不一样：它有一半的工作量在手机的「系统设置」里，不在代码里。**

我实测过：**在还没配置系统设置的情况下，崩溃自恢复的成功率只有 50%** ——
4 次测试里成功了 2 次。系统日志给出了原因：

```
mAllowStart_noBinding=PROC_STATE_TOP
```

这是荣耀 MagicOS 的「应用启动管理」在起作用：**默认只允许应用在前台状态时被后台启动**。
这是系统层面的限制，**代码绕不过去**，必须在设置里手动放行。

> ⚠️ 所以：**不做下面第二节的设置，这个应用就不可能通过最终验收。**

---

## 〇点五、两项已经做出的决定（2026-10）

### 决定一：开机自启**保留代码，但不作为验收卡点**

实测发现：**重启后 adb 连不上手机** —— 手机停在锁屏上。

根因是 Android 的加密存储机制：本应用用 SharedPreferences 存配置（属于"加密存储"），
**加密存储在用户首次解锁前不可用**，所以 App 无法在锁屏状态下启动。
这不是 bug，是系统设计，代码绕不过去。

用户决定不为这个功能改锁屏设置，因此：

- 代码**保留**（零成本，且锁屏密码一旦关掉就能立刻生效）
- 但**不再作为 M4 的验收条件**
- 章程里"重启后自动恢复值守"这条标准**实质上划掉**

> **代价（如实记录）**：半夜跳闸 → 手机重启 → 停在锁屏 → 无人解锁 → 整晚零值守，
> 而且第二天不会有任何提示。
>
> 如果哪天改主意：设置 → 安全和隐私 → 锁屏密码 → 无，然后重新实测即可。

### 决定二：新增「退出值守」按钮

放在设置对话框里（需长按左上角信息条 2 秒才能进），点击后**二次确认**。

⚠️ 退出的实现顺序**不能错**，错了会出现"用户以为退出了、其实还在跑"：

```
① 先解除外部看门狗闹钟   ← 否则 5 分钟后它会把服务重新拉起来
② 再停止前台服务        ← stopService 同时取消 START_STICKY 的重启
③ 最后关闭界面          ← 若先关界面，服务的界面看门狗 45 秒后会把界面拉回来
```

### 退出功能的真机验证结果（已通过）

| 检查 | 结果 |
|---|---|
| 界面退到桌面 | ✅ |
| 前台服务停止 | ✅ |
| 看门狗闹钟 | ✅ 处于 `alarm_cancelled` 状态（在"已取消"历史里，不在待触发列表） |
| 常驻通知 | ✅ 消失 |
| 进程 | ✅ 只剩空的缓存进程，无组件在跑 |
| **持续观察 7 分钟**（超过 5 分钟看门狗周期） | ✅ **没有任何东西把它拉回来** |
| 退出后重新打开 | ✅ 进程、服务、通知全部正常恢复 |

## 一、架构：为什么拆成"服务 + 界面"两层

Android 15 起禁止从 `BOOT_COMPLETED` 启动 `camera` 类型的前台服务。
本项目 targetSdk = 36，这条限制直接生效 —— "开机起个带相机的前台服务"这条路走不通。

所以拆成：

| 组件 | 职责 | 为什么 |
|---|---|---|
| `MonitorService`（`specialUse` 类型） | 常驻通知 + 看门狗 + 拉起界面 | `specialUse` 不在 Android 15 的限制名单里，开机可以起 |
| `MainActivity` | 持有相机、识别、报警 | 界面可见时访问相机天然合法 |
| `BootReceiver` | 开机拉起服务 | 标准路径 |
| `WatchdogReceiver` | 闹钟兜底 | 系统投递闹钟时会主动拉起应用，**不依赖应用自己还活着** |

### 三层看门狗

| 层 | 检测什么 | 恢复方式 | 实测 |
|---|---|---|---|
| 相机看门狗 | 画面连续 10 秒不出帧 | 重建相机会话 | 已实现 |
| 界面看门狗 | 界面 45 秒没发心跳 | 服务重新拉起界面 | ✅ 验证通过 |
| 进程看门狗 | 进程被杀 | `START_STICKY` 自动重启 | ⚠️ **50%** |
| 外部看门狗 | 以上都失效 | 闹钟广播唤醒应用 | 已布防 |

## 二、⚠️ 必须手动完成的系统设置（六个，一个都不能少）

> **技巧**：MagicOS 的设置页顶部有个**搜索框**，直接输入关键词能一步跳过去，
> 比一层层点进去快得多，也不容易走错版本不同的路径。

### ① 应用启动管理 —— **最关键的一个**

**设置 → 应用 → 应用启动管理 → 找到「加油站车辆报警」**

1. 关闭右侧的 **「自动管理」** 开关
2. 弹出的小窗口里，**三个开关全部打开**：
   - ☑ 允许自启动
   - ☑ 允许关联启动
   - ☑ 允许后台活动

> 这一步直接决定崩溃/重启后能不能自动恢复值守。
> 实测未配置时恢复率只有 50%，配置后应接近 100%（**配置完必须重新实测**）。

### ② 显示在其他应用上层

**设置 → 应用 → 应用管理 → 加油站车辆报警 → 特殊访问权限 → 显示在其他应用上层 → 允许**

> 这是 Android 上【后台启动界面】的唯一可靠豁免。
> 没有它，看门狗拉不起值守界面，「自动恢复值守」就是空话。
> 顺带还让报警界面能盖在其它应用之上。

### ③ 电池优化

**设置 → 电池 → 更多电池设置 → 应用耗电管理 → 加油站车辆报警 → 允许后台高耗电**

> 不设置的话，系统会在省电时直接冻结本应用。

### ④ 后台加锁

**打开最近任务（从屏幕底部上滑并停住）→ 找到本应用的卡片 → 下拉 → 点锁图标**

> 防止手滑清后台时把值守一起清掉。

### ⑤ 通知权限

**设置 → 通知 → 加油站车辆报警 → 允许通知**

> M4 的常驻通知靠它。没有通知，部分 ROM 会认为前台服务"不可见"而直接杀掉。

### ⑥ 勿扰模式允许闹钟 —— **这条决定报警能不能响**

**设置 → 声音和振动 → 勿扰模式 → 允许例外 → 打开「闹钟」**

> M3 的报警走的是闹钟音频通道，靠的就是这条豁免。
> **如果勿扰被设成「无例外 / 完全静默」，报警将没有任何声音** ——
> 这是应用层面无法绕过的，只能靠系统设置。

## 四、常见问题

### 问题 1：重启后 App 没有自动起来

按顺序排查：
1. **第二节第 ① 项「应用启动管理」配了吗？** 这是最常见的原因
2. 第二节第 ② 项「显示在其他应用上层」配了吗？没有它看门狗拉不起界面
3. 第二节第 ③ 项电池优化配了吗？
4. 用日志确认开机广播有没有收到：
   ```
   adb logcat | grep GasGuard
   ```
   看到 `收到广播：android.intent.action.BOOT_COMPLETED` 说明代码这侧没问题，
   问题在系统拦截。

### 问题 2：崩溃后有时能恢复、有时不能

**这就是第二节第 ① 项没配的表现**（实测未配置时恢复率约 50%）。
配好「应用启动管理」后重新跑第五节的 5 次测试。

### 问题 3：通知栏里没有「值守中」

1. 检查第二节第 ⑤ 项通知权限
2. 检查有没有把通知渠道手动关掉（设置 → 通知 → 加油站车辆报警 → 值守状态）

### 问题 4：按 Home 后界面回不来

**几乎一定是缺「显示在其他应用上层」权限。**
Android 从 10 起限制后台启动界面，这个权限是唯一可靠的豁免。
日志里会明确写出来：`拉起值守界面失败。多半是因为没有授予「显示在其他应用上层」权限`。
