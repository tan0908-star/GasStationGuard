## 〇、本阶段做了什么

从这一版开始，**这个 App 真的会叫人了**。

| 模块 | 说明 |
|---|---|
| **监测区域 ROI** | 只统计"车进入我关心的那块地面"，挡住马路过的车、对面灯光、树影 |
| **多帧确认** | 滑动窗口 8 帧内命中 ≥3 帧才报警（单帧漏检被时间冗余吸收） |
| **强制报警** | 三条通道同时上：**警报音 + 震动 + 中文语音** |
| **解除方式** | 唯一的解除方式是**长按「已到岗」2 秒**（按钮上有绿色进度条） |
| **自动拨号** | 30 秒无人解除 → 自动拨打紧急号码（最后一道防线） |

> ⚠️ 这一版仍然**不具备 8 小时后台值守能力**（那是 M4）。
> 目前切后台/熄屏后 App 会停。M4 完成前不要真正拿去值守。

## 二、⚠️ 本轮踩到的关键坑：语音"播了但听不见"

### 现象

用户反馈"报警时只听到警报声，没听到人说话"。但系统日志显示 TTS 引擎**明明连接成功了**：

```
TextToSpeechManagerPerUserService: Connected successfully to TTS engine: com.hihonor.voiceengine
```

**语音确实播了，就是听不见。**

### 根因

**TTS 默认走「媒体」音频通道，而警报声走「闹钟」通道。**

值班时媒体音量经常被调得很低甚至静音（刷视频怕吵、游戏静音…），
结果就是**"警报声震天响，人的说话声完全被淹没"** —— 语音这条通道等于白做。

而语音恰恰是三条通道里**信息量最大**的一条：光有"嘟嘟嘟"值班的人不知道发生了什么，
听到"有车辆进入，请到岗查看"才会立刻明白。

### 修复

```kotlin
tts.setAudioAttributes(
    AudioAttributes.Builder().setUsage(AudioAttributes.USAGE_ALARM).build()
)
```

把语音也挂到闹钟通道 —— 同一个音量、同样能穿透勿扰。

**另外**：播报时把警报音自动压到 25%，否则两个声音叠在一起听不清说的是什么。

### 教训

**"代码执行了"和"用户感知到了"是两回事。**
这个坑只有真机、真人、真耳朵才能发现 —— logcat 里一切正常。

## 三、监测区域（ROI）怎么设

### 操作

**长按画面 2 秒 → 不松手直接拖出一个矩形 → 松手保存**

故意用长按而不是点一下：防止值班时手碰到屏幕误改设置。

被框选的区域会**高亮**，区域之外会**压暗**，一眼就能看出"我现在只盯哪块"。

### 应该框哪里

框**车辆会经过的地面**，比如加油站入口的通道。

**不要**把马路、对面楼房、树梢框进去 —— 每多框一点，误报就多一点。

### 为什么这一步很关键

没有 ROI，画面里所有会动的东西都是候选：马路上的过路车、对面窗户的灯光反光、
树枝晃动、雨点。误报率会直接爆表，然后这个工具就会因为"太吵"被关掉 ——
**那是最严重的失败，比偶尔漏一次还严重。**

## 四、多帧确认是怎么工作的

```
每一帧（2 fps）：
    识别到车？ → 车框中心落在 ROI 里？ → 这一帧算"命中"
                ↓
    维护最近 8 帧的命中记录
                ↓
    8 帧里命中 ≥ 3 帧  →  确认有车 → 立即报警
```

**为什么这么做**：单帧检测一定会抖，同一辆车这帧检出、下帧漏检是常态。
但一辆车开进加油站会停留好几秒（按 2fps 就是十几帧），
只要其中几帧检出就能确认 —— **单帧漏检被时间维度的冗余吸收掉了**。

### ⚠️ 一个刻意的取舍（已知缺口）

报警被解除后，必须**先出现 3 帧"区域内没车"**才会重新武装。

副作用：**如果一辆车还停着、第二辆车又开进来了，这期间不会再次报警。**

我选择接受它，理由是：**报警的目的是把人叫醒**。值班人员按了「已到岗」
说明人已经醒了、正在处理，此时第二辆车的风险远低于"误报刷屏导致工具被弃用"。

这个缺口已记入已知问题，M6 应引入目标跟踪（给每辆车一个 ID）来彻底解决。

## 五、怎么在没有车的时候测试报警

调试触发入口（**仅 debug 版生效，release 版这段代码根本不编译生效**）：

```bash
adb shell am start -n com.gasstation.guard/.MainActivity --ez debug_alarm true
```

启动约 2 秒后会自动触发一次报警，用来验证"报警通道到底响不响"。

> ### ⚠️ 安全设计：调试触发时拨号延时会自动拉长到 5 分钟
>
> **这是用真实事故换来的。**
> 2026-10 测试期间，用户已经填入了真实号码，而我们连续跑了几次报警却没在 30 秒内停掉 ——
> 自动拨号很可能真的拨了出去。之后加了这道防护：
> **调试入口触发的报警，拨号延时强制为 300 秒**，自动化测试不可能误拨。
>
> 要测真正的 30 秒拨号，必须由人盯着，并且事先确认号码填的是谁的。

## 七、已知问题

1. **上面的"第二辆车"缺口**（第四节）—— 解除后需画面清空才重新武装。
2. **自动拨号未经真机验证**（只有一次可能误拨、无法确认）。需要一次受控测试。
3. **App 切后台/熄屏就停** —— M4 解决。
4. **无 8 小时长稳验证** —— M4 之后才能做。
5. **TTS 语音包依赖机型** —— 如果设备没有中文语音包，报警界面上会显示 `语音✗(缺中文语音包)`，此时只有铃声+震动，不会静默失败。
6. **勿扰"无例外"模式下声音仍会被系统拦掉** —— 这是系统层面的，应用无法绕过；安装时要在系统设置里确认。
