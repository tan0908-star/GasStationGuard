# M6 操作手册 —— 温控 + 自适应帧率 + 隐藏设置页

> 真机：荣耀 200 / MagicOS 10.0.0.175 / Android 16 (API 36)
> 这是最后一个里程碑。

---

## 〇、本阶段做了什么

| 模块 | 说明 |
|---|---|
| **温度保护** | 45°C 降载、50°C 暂停识别并**语音警告**，降到 47°C 以下自动恢复 |
| **自适应帧率** | 识别频率随温控档位自动调整（正常 2fps → 降载 0.67fps → 暂停） |
| **隐藏设置页** | 长按左上角信息条打开：号码、长按时长、**监测区域、灵敏度、频率、音量**、系统权限、告警记录、退出 |

> "隐藏"的含义：入口需要**长按 2 秒**，不是普通页面。
> 值守时手碰到屏幕不会误改设置，但你知道在哪。

---

## 一、为什么设置页用「对话框」而不是独立页面

独立 Activity 一打开就会让主界面走 `onStop` → **相机被释放** → 那段时间**没有值守**。

设置页恰恰是用户可能停留比较久的地方（尤其第一次配置的时候）。
让它悄悄关掉值守是完全不可接受的，所以坚持用对话框 —— 主界面始终保持前台，相机不中断。

---

## 二、⚠️ 关于「50°C 暂停识别」这个决定的取舍

温度到 50°C 时暂停识别，意味着**这段时间没有车辆检测，会漏报**。
按章程要求显式标出：

**我选择暂停，理由是：**

1. 50°C 的电池温度已经进入危险区，继续全速跑是在拿设备安全赌。
   这是一台放在值班室、**没人在旁边看着**的设备。
2. 暂停时**用中文语音明确播报**，并在屏幕上挂出橙色警告横幅。
3. 暂停是**自动恢复**的，温度降下来自己就继续。
4. 真正不可接受的是"悄悄不工作"；这里是"大声告诉你我不工作了"。

**如果实测发现夏天经常触发 50°C**，正确做法是改善散热
（别放阳光直射处、垫高留出风道、摘掉厚手机壳），**而不是把阈值调高**。
阈值按章程固定在 45/50，设置页里不开放修改。

## 三、真机验证结果（已通过）

用 `adb shell dumpsys battery set temp` **伪造电池温度**来测，不需要真的把手机加热。

| 伪造温度 | 期望 | 实测 |
|---|---|---|
| 42°C | 正常，间隔 500ms | ✅ `温度：42.0°C 正常` / `间隔 500ms` |
| 52°C | 暂停 + 警告 | ✅ `温度：52.0°C 已暂停识别` + 橙色横幅 |
| 42°C（回落） | 自动恢复正常 | ✅ `温度：42.0°C 正常` / `间隔 500ms`，横幅消失 |

复现命令：
```bash
adb shell dumpsys battery set temp 520   # 52.0°C → 应暂停并语音警告
adb shell dumpsys battery set temp 420   # 42.0°C → 应自动恢复
adb shell dumpsys battery reset          # 停止伪造，恢复真实电池数据
```

> ⚠️ 测完**一定要 `reset`**，否则手机电量/温度显示会一直是假数据。

## 四、设置页各项的含义与风险

| 设置项 | 默认 | 调它的风险 |
|---|---|---|
| 紧急联系电话 | 空 | 空 = 不自动拨号（报警界面会明确提示） |
| 解除长按时长 | 2 秒 | 调短 → 报警时手擦过屏幕就误解除 = **漏报**。下限硬锁 1 秒 |
| **监测区域** | 整幅画面 | 不框选 → 马路过的车、灯光、树影都会触发误报 |
| **识别灵敏度** | 0.35 | 调低更易报警也更易误报；调高更少误报但夜间可能漏车 |
| **识别频率** | 500ms | 调稀更省电更不热，但**更容易漏车**（快速驶过的车可能只出现一两帧） |
| **报警音量** | 最大 | 每降一档，叫醒成功率就低一档 |
| 温度保护阈值 | 45/50°C | **不开放修改**（章程固定值） |

**界面上对每一项都写了风险提示**，因为这几项的共同点是：
调错了不会立刻发现，等发现的时候往往是漏了一次报警。

## 五、验证清单（M6）

| # | 检查项 | 应该看到什么 | 通过？ |
|---|---|---|---|
| 1 | 诊断条 | 多出「识别：… （间隔 500ms）」和「温度：xx.x°C 正常」 | ✅ |
| 2 | 长按左上角信息条 | 设置里有「识别与温控」区 | ✅ |
| 3 | 伪造 52°C | 橙色横幅 + 语音播报「手机温度过高…」 | ✅ 横幅已验证，语音待你确认 |
| 4 | 伪造后恢复 42°C | 横幅消失，间隔回到 500ms | ✅ |
| 5 | **点「重新框选监测区域」** | 对话框关闭，进入黄虚线框选模式 | ☐ 待验证 |
| 6 | 改灵敏度/频率/音量并保存 | 诊断条上的间隔立刻跟着变 | ☐ 待验证 |
| 7 | **连跑 3 小时**（真实班次长度） | 温度是否稳定、有无触发降载 | ☐ **最重要的一项，未做** |

> **第 7 项是整个项目最后的验收动作。**
> 值班时长是 2–3 小时，所以不需要 8 小时；但必须真的跑满一个班次，
> 看温度曲线、看有没有掉线、看误报率。

## 七、已知问题

1. **长时间运行的温升曲线未实测**（清单第 7 项）。
2. **温度读取依赖粘性广播**，个别 ROM 可能不提供 —— 代码里读不到时会保持原档位而不是盲目降载
   （"因为测不到所以不工作"本身就是一种漏报理由）。
3. **暂停期间会漏报**（见第二节，已显式标注并有语音警告）。
4. **温控阈值不开放修改**（章程固定值）。
