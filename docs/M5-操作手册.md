# M5 操作手册 —— 告警取证 + 自动清理 + 导出

> 真机：荣耀 200 / MagicOS 10.0.0.175 / Android 16 (API 36)
> 前置：M1–M4 已完成

---

## 〇、本阶段做了什么

每次报警都会自动留下一份**可回看的证据**：

| 内容 | 说明 |
|---|---|
| `clip.mp4` | **约 14 秒**画面：报警**前**约 6 秒 + 报警后 8 秒 |
| `photo.jpg` | 报警瞬间的**全分辨率照片**（1280×720，用于看清车型/车牌） |
| `info.txt` | 告警时间、帧数、检出的车型与置信度、编码详情 |

**自动清理**：超过 7 天自动删除。
**手动删除**：设置里可以随时清空（录到顾客或无关画面时用）。
**导出**：打包成 zip 分享到微信/邮件等。

---

## 一、为什么录像要包含"报警前"的画面

**这是 M5 最容易做错的一点。**

报警是在车已经进入监测区域、并且连续命中好几帧**之后**才触发的。
如果等报警响了才开始录，**车早就开进来了** —— 最关键的那几秒恰恰在报警之前。

所以实现上是一个**环形缓冲**：一直在内存里滚动保留最近约 6 秒的画面（12 帧），
报警时才把这些帧倒出来，接上报警后的 8 秒，一起编码。

## 二、⚠️ 一个重要的技术取舍：为什么不用 CameraX 的 VideoCapture

章程写的是"10 秒视频"。直觉做法是给相机加一个 `VideoCapture` 用例，但**没有这么做**。

**理由**：加 `VideoCapture` 会**改变相机会话配置**，而 M1–M3 验证过的相机链路
（夜视参数、1280×720、长时间稳定性）是全项目最不能冒险的地方。
会话配置一旦失败，直接后果是**相机起不来 = 漏报**。

所以走的是**零相机风险**的路：**把已有的分析帧自己编码成 MP4**。

| | VideoCapture | 分析帧编码（本方案） |
|---|---|---|
| 碰相机链路 | ⚠️ 会改会话配置 | ✅ 完全不碰 |
| 帧率 | 可到 30fps | **2fps**（和识别帧率一致） |
| 画面内容 | 高帧率但可能和识别看到的不一样 | **每一帧都是模型真正看到的那一帧** |
| 排查漏报 | 帮助有限 | **直接对应** |

代价是看起来像快放幻灯片；但对于"车有没有进来、进来的是什么车"这个用途足够，
而且对排查"为什么这辆车没报警"更有价值。

## 三、⚠️ 本轮踩到的三个坑（全部是静默失效）

这三个都是**不报错**的，只有把诊断写出来才发现。

### 坑 1：`recycle()` 写在了前面

`offerFrame(frame)` 一开始写在 `frame.recycle()` **之后**，
于是传进去的是**已经被回收的 Bitmap**，压缩 100% 失败。

现象：证据目录建好了、`info.txt` 也写了，**只是里面一帧都没有**。

### 坑 2：`MediaMuxer` 是 `stop()` 时才刷盘的

文件大小在 `release()` **之前**检查，长度永远是 0，
于是一个**完好生成、572KB 的 MP4 被判定为"失败"并删除**，用户拿不到录像。

### 坑 3：`signalEndOfInputStream()` 只支持 Surface 输入

我们用 buffer 输入（`getInputImage`），调用它会抛
`IllegalStateException: signalEndOfInputStream() called without an input surface set`。
正确做法是送一个 `size=0` 且带 `BUFFER_FLAG_END_OF_STREAM` 的输入缓冲。

### 教训

**这台手机的 ROM 会把应用日志冲掉，只能靠"把诊断写到能被看到的地方"来定位。**

本轮的做法：把编码器的 `送入/跳过/写出样本数/文件大小/最后错误`
全部写进 `info.txt`，并在报警界面上显示录像器的计数器。
坑 1 就是靠屏幕上的 `调用34 压失败34 环形0` 一眼定位的。

## 四、真机验证结果

| 项 | 结果 |
|---|---|
| 告警自动录像 | ✅ 28 帧 / 约 14 秒 |
| MP4 是合法视频 | ✅ 顶层 box `ftyp, moov, free, mdat`；时长 14.0 秒；含 H.264 配置 |
| 告警照片 | ✅ **1280×720** 全分辨率，方向正确 |
| info.txt | ✅ 含时间、帧数、检出、编码详情 |
| 手动删除全部记录 | ✅ 目录清空 |
| 一键导出 | ⚠️ 代码完成，**未在真机点过**（见验证清单） |
| 7 天自动清理 | ⚠️ 代码完成，**需要时间验证**（见下方说明） |

### 关于 7 天自动清理怎么验证

不可能真的等 7 天。验证方法：**改手机时间**到 8 天后，重启 App，看旧目录是否被清掉。
注意代码里有一道保护：**今天的目录无论如何不删**，所以改时间时要确认旧目录的时间戳确实在 7 天前。

## 五、怎么用（给值班的人）

### 看录像
拔下数据线连电脑，或直接在手机的**文件管理**里进：
```
Android/data/com.gasstation.guard/files/evidence/<时间戳>/
```
⚠️ Android 11 起部分文件管理器打不开 `Android/data`。打不开就用下面的一键导出。

### 一键导出
长按左上角信息条 → 设置 → **「导出全部记录（打包分享）」**
会打包成 zip，然后选择发给谁（微信/邮件/网盘都行）。

### 手动删除
长按左上角信息条 → 设置 → **「删除全部记录」** → 二次确认

> 录到顾客、车牌、无关路人时，可以随手清掉，不必等满 7 天。

## 八、已知问题

1. **视频只有 2fps**（见第二节的取舍说明）。如果需要更流畅，可以只提高**录像**帧率
   而不动识别帧率 —— 那需要把取帧和识别解耦，是 M6 可以考虑的优化。
2. **`Android/data` 目录在部分文件管理器里打不开**，只能靠一键导出。
3. **7 天清理未做时间验证**（见第四节）。
4. **导出功能未在真机点过**（见清单第 5 项）。
5. **录像期间内存占用**：环形缓冲 12 帧 + 会话帧，一次告警最多约 60 秒 ×2fps×40KB ≈ 5MB，可接受。
