# 加油站夜班值守车辆报警 APP

一台固定在加油站值班室窗边的安卓手机，夜间值守时自动识别驶入的车辆，
并用强制报警把人叫醒。**单用户真实生产工具**，不是演示项目。

## M1 已实现

- 全屏 CameraX 预览，锁定横屏，屏幕常亮，沉浸式全屏
- 固定 **1280x720（16:9）**，为 M2 的模型提供稳定输入尺寸
- **夜视优化**（通过 `Camera2Interop` 直改 Camera2 底层参数）：

  | 参数 | 默认 | 现在 | 效果 |
  |---|---|---|---|
  | AE 目标帧率区间 | 常被锁死 30fps | 选最低帧率最小的一档 | 曝光上限从 1/30s 放宽到 **≤1/8s**，进光量约 **3.7 倍** |
  | 降噪 | 默认 | `HIGH_QUALITY` | 夜间噪点显著减少 |
  | 电子防抖 | 开 | 关 | 固定支架不需要，换回被裁掉的一圈视野 |

  **安全设计**：每一项都先查真机能力表，不支持就跳过；如果某个参数导致会话配置失败，
  会自动关闭整套夜视优化并**立即回退重试** —— 绝不让"优化"变成"相机打不开"。

- 相机状态可见 + 自动重试：权限被拒 / 启动失败 / 被系统抢占，屏幕中央都会出现红字
- 左上角诊断条：状态 / 分辨率 / 帧率 / 夜视参数 / 已运行时长

## M2 已实现

- **模型**：YOLOv8n，**int8 全整数量化** TFLite，输入 640×640，体积 **3.25 MB**
- **类别**：只保留 **汽车 / 摩托车 / 客车 / 卡车**（COCO 80 类中的 4 类，运行时筛选）
- **推理**：LiteRT 1.4.2，4 线程 CPU，**限流 2 fps**（相机仍跑 30fps 供预览）
- **界面**：画框 + 类别 + 置信度；诊断条显示检出数量与单帧耗时
- **可复现导出**：`tools/export_yolo_tflite.py`（三步管线，含中文原理注释）
- **电脑端验证**：`tools/verify_tflite.py`（不接手机就能验证模型+解码链路）

### ⚠️ 本轮踩到并修复的致命问题：int8 量化把类别分数压成 0

YOLO 输出是 `cat([框(0~640), 分数(0~1)])`，int8 量化给整个张量**只算一个**缩放系数。
观测值域 0~656 → `scale≈2.57` → **所有 0~1 的类别分数被 round 成 0，模型完全失效，且不报任何错**。

修复：在 ONNX 图里给框分支插入 `Div(640)`，把两分支值域拉到一起。
输出 scale 从 **2.5743 → 0.00402**，框和分数都能精确表示。

**代价**：框输出变成归一化 0~1，安卓端解码需乘以 `inputSize`（代码里有醒目 ⚠️ 标注）。

**精度对照**（COCO128 前 40 张）：

| | 汽车 | 摩托车 | 合计 |
|---|---|---|---|
| PyTorch float32 原模型 | 4 | 2 | 6 |
| **int8 TFLite** | 5 | 2 | **7** |

int8 版未出现精度损失。

### int8 标定集说明

标定用 **COCO128 原图 + gamma 压暗版本**，让量化区间同时覆盖白天与夜间。
⚠️ 等 M5 能录下真实现场夜拍画面后，**应改用现场夜景图重新标定** —— 这是提升夜间识别率性价比最高的一步。

## 硬性约束

- **全离线**：无后端、无账号、无网络请求、无数据上传。
  `android:allowBackup="false"` 已关闭系统云备份。
- **M3 完成之前，本应用不能用于实际值守 —— 它不会叫醒任何人。**

## 已知问题 / 待办

1. **预览精确几何未验证**：预览用 `fitCenter` 不裁切画面，屏幕两侧应有黑边，
   "黑边宽度 ↔ 图像坐标"的映射尚未在真机上精确确认。M3 的 ROI 标定工具会解决这个。
2. **长曝光的拖影**：曝光上限放宽到 1/8s 意味着夜间移动物体会拖影。
   固定场景没问题，但快速驶过的车辆可能糊。需要真机夜测确认是否影响识别；
   届时可在 M6 的设置页里调整。
3. 权限首次弹窗路径未测（开发阶段是用 adb 直接授权的）。
